# منوی دسکتاپ، کارت خدمات و برندها

## تغییرات

- منوی اصلی دسکتاپ: زمینه چندلایه سرمه‌ای، حاشیه روشن، pill فعال و hover با کنتراست روشن. یک لایه radial-gradient با مسیرهای تصادفی و Web Animations API حرکت می‌کند؛ به‌روزرسانی React در هر frame و timer مداوم ندارد. روی موبایل، reduced-motion یا تب پنهان حرکت آن فعال نیست. این لایه pointer-events ندارد و تنها خودش clip می‌شود؛ پنل مگامنو بریده نمی‌شود.
- منطق کلیک مگامنو، پیش‌فرض تهران، Escape و لینک‌ها حفظ شدند.
- چهار خدمت در موبایل یک ردیف با چهار ستون، در دسکتاپ چهار کارت مستقل. تصاویر اختصاصی تولیدشده به WebP با ابعاد ۳۲۰ تبدیل شدند؛ مجموع فایل‌های چهار تصویر کمتر از ۳۲ کیلوبایت است. تصویرها تزئینی و عنوان لینک نام دسترس‌پذیر است. برای برندها تصویر ساختگی تولید نشد.
- hover کارت‌ها تیره می‌ماند و متن روشن است؛ utility سفیدکننده قبلی حذف شد.
- نوار برندها سرمه‌ای/آبی خنثی است؛ هر لوگوی اصلی روی یک پلاک روشنِ متمایز قرار دارد. لوگوها معکوس‌رنگ نشده‌اند. حاشیه شفاف تصویرهای اصلی trim و نسخه نمایشی کم‌حجم در `public/images/brands/display` ساخته شد؛ فایل اصلی و منبع قبلی حفظ‌اند. حرکت پیوسته و لینک اختصاصی برندها حفظ شد.

## خطای Cloudflare RUM: اقدام بیرون مخزن لازم است

خطای جدید، CSP نیست: مرورگر اسکریپت را اجرا می‌کند ولی POST آمار به `/cdn-cgi/rum` با 404 روبه‌رو است. در کد این مخزن هیچ اسکریپت Cloudflare Analytics تزریق نمی‌شود و این مسیر پذیرش telemetry متعلق به لبه Cloudflare است، نه API سایت.

مستندات رسمی، مسیرها را جدا می‌کند:

- سایت proxied: `https://<domain>/cdn-cgi/rum`
- سایت بدون Proxy: `https://cloudflareinsights.com/cdn-cgi/rum`

منبع: https://developers.cloudflare.com/web-analytics/data-metrics/data-origin-and-collection/

بعد از خاموش‌کردن Proxy، تداوم snippet خودکار/قدیمی یا HTML کش‌شده یکی از احتمالات اصلی است؛ بدون بررسی DNS و پنل، علت قطعی محسوب نمی‌شود. برای حل:

1. Cloudflare Dashboard → Web Analytics → سایت khodrochare.ir → Manage site.
2. اگر آمار Cloudflare لازم نیست، حالت **Disable** را انتخاب کنید. این کار با خاموش‌کردن WAF/DDoS فرق دارد.
3. اگر آمار لازم است و DNS-only می‌ماند، راه‌اندازی مخصوص سایت **not proxied** را انجام دهید و snippet جدید را از همان پنل بردارید؛ در سایت proxied گزینه رسمی نصب دستی **Enable with JS Snippet installation** است. snippet قبلی و نصب تکراری در Tag Manager/پنل هاست باید حذف شود. توکن وب‌آنالیتیکس باید متعلق به همین سایت باشد؛ API token محرمانه لازم نیست.
4. فقط HTMLهای مرتبط را از کش موجود پاک کنید و با Hard Reload/پنجره خصوصی تست کنید. اگر Cloudflare دیگر در مسیر نیست، کش مرورگر، هاست و هر لایه باقیمانده را بررسی کنید؛ purge Cloudflare به‌تنهایی کافی نیست.
5. در View Source و Network دنبال `static.cloudflareinsights.com/beacon.min.js` و `data-cf-beacon` بگردید. در حالت Disable نباید درخواست جدید RUM ببینید. در نصب صحیح DNS-only، telemetry نباید به `/cdn-cgi/rum` مبدأ بدون Cloudflare برود. پاسخ 404 را با POST دستی یا داده مشتری آزمایش نکنید؛ درخواست طبیعی beacon را مشاهده کنید.

راهنمای رسمی تنظیمات: https://developers.cloudflare.com/web-analytics/get-started/

CSP قبلی اجازه origin خارجی صحیح را دارد؛ بازترکردن CSP یا خاموش‌کردن حفاظت کل دامنه، راه‌حل این 404 نیست. route صوری با پاسخ 204 اضافه نشده است؛ چنین کاری خطا را پنهان می‌کند و به معنای ثبت آمار نیست. تنظیم حساب Cloudflare از این مخزن قابل‌اجرا نیست و رفع عملیاتی این خطا هنوز به اعمال مراحل بالا در پنل نیاز دارد.
